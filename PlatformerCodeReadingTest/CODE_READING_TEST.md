# Unity 코드 읽기 평가

- 제한 시간: 60분
- 개인 작업
- AI 사용 가능. 단, 사용한 질문을 기록하고 제출 코드를 직접 설명할 수 있어야 한다.

## 할 일

1. 프로젝트를 실행하고 코드를 읽는다.
2. 이 프로젝트의 코드 실행 흐름을 순서도로 작성한다.
3. 앞 화면에서 지정받은 A/B/C/D 기능 하나를 실제로 구현한다.
4. 기능이 작동하는지 Unity에서 확인한다.
5. 답안과 변경 코드를 commit, push하고 PR을 만든다.

## A/B/C/D 기능

### A — 미끄러운 바닥

일부 바닥에서는 이동키를 놓아도 플레이어가 더 오래 미끄러지게 만든다.

### B — 단단한 벽돌

아래에서 두 번 맞아야 깨지는 새로운 벽돌을 만든다.

### C — 목숨 세 개

플레이어가 세 번 사망하면 부활하지 않고 게임 오버가 되게 만든다.

### D — 시간 보너스

골인하면 남은 시간 또는 빠른 기록에 따라 보너스 점수를 받게 만든다.

## 제출

답안은 `Analysis/<GitHub아이디>.md`에 자유 형식으로 작성한다.

순서도 형식과 추적 범위는 스스로 정한다. 단, 실제 클래스와 메서드 이름을 사용해야 한다.

평가는 코드의 양보다 다음 내용을 중요하게 본다.

- 기존 코드의 실행 순서를 이해했는가?
- 기능을 어느 클래스에 넣을지 판단했는가?
- 기존 구조를 재사용했는가?
- 자신이 바꾼 코드를 설명하고 현장에서 수정할 수 있는가?
